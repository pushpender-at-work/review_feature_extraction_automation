Problem Statement

Product: An e-commerce shopping application where thousands of customers write product reviews daily. Currently, the product team manually reads reviews to understand which product features (battery, camera, screen, price, delivery, etc.) customers are talking about — this doesn't scale as review volume grows, and insights come too late for quick decision-making.

Problem: The company needs a backend service that other teams/apps (like the analytics dashboard or the customer support tool) can call anytime to automatically extract product features mentioned in a review, using POS Tagging (Nouns = features). Right now this logic only exists as a script — it needs to be turned into a proper API so it can be integrated into the larger product system.

Goal: Build a FastAPI-based REST API that:

Accepts one or more customer reviews as input
Uses spaCy POS tagging internally to extract feature-related nouns
Returns the extracted features (and their frequency, for bulk reviews) as a JSON response

Benefit: Any team or application in the company can now hit this API endpoint anytime and instantly get structured feature data from raw review text — no manual reading needed, real-time insights, and it can be plugged into dashboards, alerts, or reports.

Input / Output Specification
Endpoint 1: Single Review

Input (JSON body sent to API):

json
{
  "review": "The battery life is amazing but the camera quality is poor."
}

Output (JSON response from API):

json
{
  "review": "The battery life is amazing but the camera quality is poor.",
  "features": ["battery", "life", "camera", "quality"],
  "feature_count": 4
}
